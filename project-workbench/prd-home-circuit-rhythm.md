# 首页"每一个名字"章节节奏优化 —— 方案（待 Jinke 拍板）

> 撰写：Kimi 客户端 · 2026-09-14
> 状态：**待拍板**，未排期。拍板后可追加为 visual-fix-2 交给 Kimi Code。
> 背景：Codex 视觉升级走查发现首页过长。本文件只讨论 `#circuit` 章节（"每一个名字，都是赛道的一部分。"），不动其他章节。

## 问题是什么（实测数据，1440×900）

| 指标 | 数值 |
|------|------|
| 首页总高 | 33,615px（约 37 屏） |
| `#circuit` 章节高 | **21,470px，占全页 64%** |
| 地名条目（.circuit-stop） | 43 条，合计 20,385px |
| 有档案/照片的条目（12 条） | 平均 769px |
| 纯地名条目（31 条） | 平均约 360px |

矛盾点：这一节的设计概念是"把弯道连成一圈"的滚动叙事（左侧粘性地图 + 右侧 43 个阅读步骤联动），概念本身成立；但 31 条"沿途地名"条目与 12 条"弯道故事"条目用了几乎相同的隆重版式（大衬线标题 + 意大利体德文 + 段落 + 前后导航 + 来源链接），信息价值不对等，滚动疲劳集中在后半段。

## 成功标准

- 首页总高 33,615px → **≤ 24,000px**（降幅 ≥ 28%）。
- `#circuit` 章节 21,470px → **≤ 11,500px**。
- 43 处地名**全部保留、全部可达**（内容不删，只改呈现密度）。
- 地图 ↔ 条目双向联动、reading-position 进度、"返回导览"导航不丢失。
- prefers-reduced-motion 与移动端（390px）行为正常；`npm test` 全过（涉及 reading-position / full-track-guide 测试需同步更新）。

## 三个候选方案

### 方案 A：密度分级（保守）

- 12 条"弯道故事"保持现有卡片版式；31 条"沿途地名"压缩为紧凑行（约 130–150px：序号 + 中文名 + 德文名 + 一行说明，去掉逐条的前后导航与来源链接，来源合并为章节末尾一条脚注）。
- 优点：改动最小，滚动叙事完整保留；缺点：估算章节仍有约 14,500px，全页约 26,700px，**达不到成功标准**。

### 方案 B：分段折叠 + 密度分级（推荐）

- 以 12 条"弯道故事"为锚点，把其间连续的纯地名条目收进"区间摘要"折叠块，例如：`Hatzenbach → Flugplatz · 之间还有 3 处地名 ∧`。
- 默认折叠：摘要块每个约 80px，滚动路径只停在 12 个锚点 + 摘要块上；点击展开后，该区间内地名以方案 A 的紧凑行呈现，仍参与地图联动。
- 估算章节高度：章节头 ~600 + 12 锚点 × 770 + 摘要块 ~7 个 × 80 + 剖面带 ~700 ≈ **11,100px**，全页约 23,200px，**达标**。
- 优点：叙事主线（一圈 12 个故事）变清晰，地名不丢；折叠/展开控件用 `aria-expanded` 保证可访问性。缺点：改动量中等，需新增折叠交互与分组逻辑。

### 方案 C：放弃滚动叙事，改地图索引（激进）

- 整节改为"大地图 + 43 地名索引网格"，点击索引在地图上定位并弹出解说卡。章节可压到约 2,500px。
- 缺点：**推翻本章"把弯道连成一圈"的概念**，与上一轮拍板的导览叙事方向冲突，不推荐。

## 推荐方案的验收标准（方案 B）

1. 1440×900 下 `#circuit` ≤ 11,500px、全页 ≤ 24,000px（用测量脚本复核，方法见下）。
2. 默认折叠状态下，43 处地名仍可通过展开 + 地图点选 + 移动端下拉全部到达。
3. 地图上点选折叠区间内的地名时，所在区间自动展开并滚动到位。
4. 折叠控件键盘可操作（button + aria-expanded），reduced-motion 下无展开动画。
5. 移动端（390×844）单列布局正常，紧凑行不挤压触控目标（≥44px）。
6. `npm run build`、`npm test` 通过；Lighthouse 复测 a11y/SEO 保持 100、CLS ≤ 0.01。
