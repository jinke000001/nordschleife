## T1 首页 #circuit 章节默认态再压缩（节奏）

**问题**：12 个锚点完整卡 + 区间摘要块连续排布，#circuit 默认态约 11,000px，阅读节奏仍被拖垮（评审问题 1）。

**方案（Jinke 已拍板方向：静态密度分级，不做滚动驱动的自动展开——保 CLS）**：

- 前 **2 个锚点**（萨宾娜弯、哈岑巴赫弧线）保持现有完整卡片版式不变（开局吸引力）。
- 其余 **10 个锚点**默认降级为紧凑行（复用现有纯地名紧凑行版式：序号 + 中文名 + 德文名 + 一句话），行尾加"展开完整讲解"按钮；点击后在原地展开为现有完整卡片（含照片、前后导航、"完整弯道档案"链接），再点可收起。`<button aria-expanded>`，键盘可操作。
- 区间摘要块（≥2 条纯地名的折叠块）逻辑不变；其内部展开后的紧凑行不变。
- 地图点选 / 下拉 jumpTo 到某个已降级锚点时：该条目自动展开并滚动到位（现有 `jumpTo` 路径延伸，参考区间展开的既有实现）。
- 移动端（≤999px）行为一致；`.story-static` 静态回退与 reduced-motion 下全部展开呈现（现有回退语义不变）。

**量化验收**：

- 1440×900 默认态实测：`#circuit` ≤ 7,000px、全页 ≤ 20,000px（执行时先记基线再对比）。
- 43 处地名 + 12 个锚点全部可达：滚动（展开后）、地图点选、移动端下拉三条路径复测通过。
- 展开/收起操作 CLS 无累积位移（Lighthouse CLS 红线兜底）。

## T2 "17 篇档案 vs 43 处地名"口径说明（理解门槛）

**问题**：两个数字并存但无任何解释，初次接触者会怀疑内容不全（评审问题 2）。

**改动（纯文案 + 链接，两处）**：

1. `/corners` 页头（"17 篇弯道档案"导语区）加一句 + 链接，建议文案：
   「北环沿途共有 43 处地名，其中 17 个弯收录了完整档案；其余地名的沿途故事，见首页的赛道地图章节。」链接指向 `/#circuit`。
2. 首页 `#circuit` 章节头（"43 处地名，串起完整的北环。"之后）加一句 + 链接，建议文案：
   「这 43 个名字中，12 个带有照片与四段讲解；另有 5 个弯因暂无实拍照片以紧凑行呈现。17 篇完整弯道档案见弯道档案页。」链接指向 `/corners`。
   - 若执行时发现锚点数量、无照片弯名单与上述不符，以数据为准修正文案并在报告中说明。

**验收**：两处文案在 1440 与 390 下均不换行错乱；链接可达；无其他文案改动。

## T3 次级文字对比度提一档（可读性）

**问题**：照片署名、来源、复核日期、meta 行等小字对比度约 4.2–4.6:1，低于 AA 小字标准 4.5:1（评审问题 3）。

**方案**：

- 以纸面底色实测为准，把全站 **≤13px 的次级文字**（署名、来源、复核日期、kicker 之外的 meta、轨道标签非激活态等）统一提到 **≥ 4.5:1，目标 ~5.3:1**（参考深度 `#5c665a`–`#565f54` 档）。
- 重点排查：`guided-story.css`、`home-story.css`、`corners.css`、`lap-archive.css`、`brands.css`、`site.css` 中所有 `#6f756c`、`#66705f`、`#5d665e` 级别的灰绿小字；`#5d665e`（约 5.3:1）可作为合并目标 token。
- 不改动：大字号导语、正文、`#bf3327` / `#a62b20` 红色强调（仅用于加粗大号场景）、深色底上的浅色文字。
- 报告中列出每个修改的 token：旧值 → 新值 → 实测对比度（修改前后）。

**验收**：抽查 5 处 meta 文字计算对比度全部 ≥ 4.5:1；Lighthouse a11y 保持 100；视觉上不破坏"浅淡克制"的层级意图（只提半档，不要改成重灰黑）。

## T4 移动端顶栏收纳（首屏）

**问题**：≤760px 下导航四项平铺折行，header min-height 128px，Hero 首屏信息被挤压（评审问题 4）。

**方案（二选一，优先 A；若实现成本明显更高再选 B，报告里说明取舍）**：

- **方案 A（推荐，纯 CSS）**：≤760px 时导航改**单行横向滚动**（`overflow-x: auto`、隐藏滚动条、首尾留白、当前项可见），header 总高 ≤ 96px，四项导航仍全部一可达。
- 方案 B：汉堡菜单 + 抽屉（可参考旧版已删除抽屉的 portal/Escape/焦点循环实现，代码在 git 历史里）。
- 导航字号、触控目标 ≥44px、focus-visible 焦点环不变；`return-to-guide` chip 行为不受影响。

**验收**：390×844 下 header 实测高度 ≤ 96px，Hero 标题在首屏可见占比明显提升（截图前后对比）；导航四项均可触达；无水平页面级滚动条（导航自身横滑除外）；Tab 键仍可进入全部导航项。

## T5 桌面端 43 地名快速定位（回访效率）

**问题**：桌面端只能靠滚动或点击地图小字热点找特定弯（评审问题 5）。

**方案**：

- 现有 `.circuit-mobile-select`（全量 43 地名下拉，移动端）在**桌面端同样显示**：建议改名为 `.circuit-jump-select` 之类的中性类名，放大地图区工具行（`guide-visual-meta` 一行附近），桌面与移动端共用同一组件与样式。
- 复用现有 `jumpTo`：选中即联动地图高亮 + 右栏讲解 + 滚动到位，与移动端行为完全一致。
- 键盘可操作（原生 select 即可）；在 1000–1280px 的中等桌面宽度下不与地图重叠、不折行。

**验收**：桌面 1440 与 1280 下下拉可用且含全部 43 项；选中"旋转木马"后地图高亮、右栏切换、滚动到位三步实测通过；移动端原有下拉功能无回归。
